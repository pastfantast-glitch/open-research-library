01 / FINDINGS

流程能串起來，角色仍需要人工驗收

本次以一張動漫女性戰士的正面 T-pose 設定圖，測試 Tripo Agentic Canvas 能否在聊天室指令下完成分件參考、Smart Mesh、UV、紋理與 AI 3D Lab 組裝。研究者親自操作網站並提供過程截圖；Codex 協助擬定提示詞、整理操作過程、證據與結果。

已跑到組裝與反覆修正；尚未證明可直接作為遊戲資產交付。

7 項分件皆有模型、UV 及彩色預覽，也取得三版組裝正面圖。然而配色、基底重複內容、共同對位座標與手臂／手套對齊仍有問題。Lab 曾承認沒有核對設定圖，且臉部 UV 修正沒有取得完成證據。

03 / PROCESS MAP

本次流程總覽

以下依研究者實際操作的先後記錄：送出設定圖與提示詞、確認分件、生成模型、展開 UV、生成紋理，最後進入 AI 3D Lab 組裝與修正。每個階段保留操作、系統詢問、產出與遇到的問題。

  1. 設定與確認上傳圖像，送出要求。
  2. 元素提取產出 7 張分件參考。
  3. Smart Mesh分別生成各部件模型。
  4. UV 與紋理展開 UV，再生成貼圖。
  5. Lab 組裝指定基準，組裝並修正。

這張完整畫布是在流程執行後補拍，用來說明各步驟的連接關係。下文再從第一次詢問開始，依序展開紀錄。

04 / STEP 01

確認角色分件計畫

送出提示詞後，先確認 Agent 的文字規劃

Tripo 建議保留 7 個獨立物件，先拆出部件參考，再生成低多邊形 Smart Mesh 與貼圖，最後交給 AI 3D Lab。研究者回覆「確認」，系統進入步驟規劃。

第一次詢問：確認實際生成清單

接著出現可修改或刪除名稱的部件清單。實際項目為：頭部與粉色長髮、素體、無袖長外套與腰部束帶、棕色短褲、雙棕色長靴、雙藍色露指手套、角色左臂黑色長袖與肩甲。

本步紀錄

文字規劃與清單雖都為 7 項，部件定義已改變：頭部與短褲獨立列出，雙靴及雙手套各合為一項，肩甲與長袖合併。這時應核對各項包含內容，避免把項目數相同誤認為計畫完全相同。

05 / STEP 02

元素提取：生成各部位的設定圖

使用元素提取節點

研究者確認清單後，畫布從角色設定圖分出 7 條分支。此階段先從單張圖片產生獨立的 2D 部件參考，再供後續模型生成使用。元素提取節點中央的家具與角色圖是功能示意。

本步產出：7 張分件參考圖

下列為本步完成後的各部件設定。它們分別涵蓋頭部、素體與服裝配件，後續模型由這些參考圖生成。

本步遇到的問題

素體設定已包含頭部、頭髮、淺色上衣與短褲，同時又有獨立頭部和短褲項目，產生重複範圍。深色高領內搭則在外衣參考中。這些內容歸屬應在進入模型生成前先確認。

06 / STEP 03

Smart Mesh：生成各部件模型

第二次詢問：確認模型生成計畫

分件參考完成後，Tripo 要求確認低多邊形 Smart Mesh 計畫，包括 T-pose、比例、方向、材質一致性與可選 2K 貼圖。研究者按「繼續」，開始各分件模型生成。

執行中與模型產出後的確認

執行初期先看見短褲灰模，其餘節點仍載入。之後 7 項都有模型預覽；Tripo 要求檢查輪廓、比例、相互對位，以及是否有明顯破洞或變形，再繼續 UV 展開。

本步產出：各部件線框檢視

本步紀錄

頭髮、扣件、拉鍊、靴子束帶與肩甲均可見幾何細節，但素體仍包含完整頭部與服裝外形。線框截圖能記錄外形及可見網格，尚不能驗證內部幾何、全部面型或動畫變形品質。

操作建議：聊天室要明確指定面數

原始提示只寫「低多邊形」，未提供數值面數。後來檢視的 Smart Mesh 節點顯示四邊面、目標 10,000 面、生成 1 個且紋理關閉。研究者觀察未標註面數時通常以一萬四邊面為基底；這裡記錄為本次使用經驗，不推定所有模式與版本都固定如此。節點設定與費用截圖集中在費用章節。

生成前應指定各部件目標與角色總預算，生成後核對實際面數。手套、肩甲及整個素體需要的面數不應僅由相同預設值決定。

08 / STEP 05

生成紋理並確認部件外觀

貼圖前的計畫確認

Tripo 提出依設定圖為各部件生成一致的動漫材質與色彩貼圖；需求中新增「先修正臉部 UV 問題後再貼圖」，並預告完成後交由 AI 3D Lab 組裝。

生成完成後，轉交 AI 3D Lab

7 項分件出現彩色結果。Tripo 要求檢查色彩與接縫，同時把臉部 UV 修正及整體組裝交給 Lab，提供「進入」按鈕。這裡沒有看到先修正 UV 再貼圖的完成證據。

本步產出：各分件紋理預覽

本步遇到的問題

短褲主體呈淺米色，手套增加橄欖綠、卡其與金色，黑色長袖則變成膚色至深色漸層，未保留設定的指定配色。素體上也出現外衣、腰帶、手套與長袖圖案；外衣正面主要色塊則較接近原設定。

這些是可見外觀偏差，尚不能直接歸因於 UV 或特定生成演算法。實際貼圖通道、尺寸及接縫品質仍需原始貼圖檔。

09 / STEP 06

AI 3D Lab 組裝、回饋與修正

進入 Lab，執行對位組裝

研究者送出「依照對位進行組裝」。任務要求對齊幾何特徵、接口及相對方向，避免穿插與間隙，保留零件形狀與細節。此時尚未展示成果。

Lab 詢問：以哪個角色作為基準？

Lab 檢查後表示六個檔案都置中於原點、沒有共同對位座標，當時尚未修改。它詢問以 #25 T 字角色組裝全部裝備，或只處理 #28 長靴；研究者選擇 T 字姿勢角色為基準，再次進入處理。

第一次組裝產出

角色已有完整輪廓，外衣與靴子大致就位。但畫面右側、角色自身左側的手臂出現深色袖子與膚色兩條輪廓，雙手也有疑似重疊或錯位。

研究者回報與 Lab 的更正

研究者指出「目前組裝起來看起來跟設定不一樣」。Lab 承認只檢查人體對位，沒有核對設定圖，並要求提供設定圖或具體差異，以 #31 組裝模型為基礎修正。

「上一版我自行估算並調整了零件比例，只檢查人體對位，沒有核對設定；先前說『完成』不夠準確。」AI 3D Lab 對話，E38

第二次組裝產出

這輪外衣下襬較收窄，腿部露出範圍增加，但左臂與手套仍有疑似對位問題，配色偏差也仍可見。未取得本輪完整修改指令或模型量測資料。

第三次組裝產出

再次取得正面角色預覽。這張取景更遠，左臂與雙手的疑似重疊輪廓仍未排除；無法僅憑畫面尺寸變化判定比例已修好。

本步結束時的狀態

已取得三版組裝正面畫面；研究者另回報三次修正共約 139 點。截圖版次與計費修改次數分開記錄。手臂／手套對位、臉部 UV 修復、完整配色與側背面狀況仍待驗證。

交接時的資產數量紀錄

原先生成 7 項，但 Lab 回報六個輸入。完整畫布 E41 中，獨立頭部未見連入組裝，素體本身又含頭部，因此推測使用了素體與五項服裝配件；尚需實際節點清單或模型檔確認。

Lab 回報保留六組材質、檢查四方向預覽，並提供模型與四視圖下載，尚未綁定骨架。本次未取得這些下載檔案；六組材質也不等於六個獨立物件，不能據此判定匯出驗收完成。

12 / NEXT TEST

改善做法：把要求變成可檢查的交付條件

以下是根據本次問題提出的下一輪測試設計，尚未執行，也不保證工具一定支援。應先確認功能與報價，再決定是否生成。

  1. 生成前：先核對分件清單與面數

    明列部件目標與總預算。頭部若要保留在素體，就避免額外生成一顆不使用的頭；若要獨立替換，先決定頸部接口與基底移除範圍。

  2. 參考圖階段：先修正設計偏差

    分件參考是後續生成的依據，先確認配色、左右、內搭歸屬及遮蔽關係。無法看到的背面可追加設定圖，避免完全由單視圖推測。

  3. 模型與 UV 階段：用可見成果驗收

    核對實際面數、接縫、UV 佈局與棋盤格；對臉部修正保留前後圖。只顯示 UV 已完成，仍不足以通過品質檢查。

  4. 紋理階段：逐件核對指定外觀

    同時放原設定與分件參考，檢查棕色短褲、藍手套、黑袖。確認真正的貼圖尺寸與通道；截圖不能證明已生成 Normal 或完整 PBR。

  5. Lab 組裝：把參考和資產映射一起交接

    明確說明哪個模型是基準、哪個頭部不用、手套如何取代或覆蓋素體。要求 Lab 先核對收到的參考圖與資產數，再作尺度及位置調整。

  6. 完成前：固定視角驗收並保存檔案

    用固定相機與縮放比較設定及修正版，補肩腕近照和側背面。匯出後檢查物件、材質、UV、貼圖與重複幾何；需要動畫時另作關節形變測試。

  7. 費用：逐階段記錄前後餘額

    記錄每次確認、重試與修改的範圍、扣點、耗時與產出 ID。遇到價格變動或免費重跑，保留當下畫面，不以目前單價追溯初次成本。

13 / CONCLUSION

本次案例的可用範圍與限制

Tripo Agentic Canvas 在本案例能組織並執行分件生成、UV、紋理與組裝流程，適合用於早期概念驗證和分件雛形探索；目前證據不足以支持無人工檢查即可交付角色資產。

流程上的主要成本不只在模型生成，也在確認分件、辨識材質偏差、重建對位與反覆解釋設定。Lab 的完成回報需要以具體視圖與檔案再次驗證。使用者回報約 1,139 點的總消耗，提供一次案例的成本尺度，不能視為其他角色的固定價格。

  • 一次角色、一張正面設定、單次流程及後續修正；未做跨角色或多次獨立重複實驗。
  • 沒有模型與貼圖原檔檢查，沒有對最終三角面數、UV 重疊、幾何連通性、骨架或引擎輸出作驗收。
  • 三版組裝只有正面且取景不同，不能定量比較尺寸與完整穿插情況。
  • 臉部 UV 的具體問題、修復結果與原始法線資訊未取得；本次不是 Base Color 轉 Normal 的實驗。
  • 未取得精確耗時、逐筆帳務與方案資訊，不計算效率或貨幣成本。

後續優先補充組裝模型、貼圖原檔、側背面與近照、扣點明細，再評估是否值得繼續修正或改由 Blender 人工完成。此處不將尚未做的檢查列為成功。
