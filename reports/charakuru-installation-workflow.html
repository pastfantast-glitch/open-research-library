01 / OVERVIEW

研究目的與目前結論

本次從 Windows 實際部署出發，確認 Charakuru 能否作為「角色插畫 → AI 協作製作 → VRM」的工作入口，並記錄首次使用遇到的依賴、瀏覽器與 MCP 連線問題。

Charakuru 將本地確認介面、製作腳本與 Agent Skills 整合在同一套件中。使用者負責設計選擇與視覺確認，Agent 串接圖片生成、Tripo 與 Blender。它可以組織製作流程，但啟動成功並不能證明成品品質或完整自動化能力。[1][2]

本次完成的是安裝與環境驗證。

應用可啟動、VRM 擴展可載入、Tripo 頁面可讀取，Blender MCP 的 9876 埠可連線。目前聊天未暴露 Blender MCP 工具；角色圖片、模型候選、綁定與最終 VRM 尚未製作，不能記為全流程成功。

03 / INSTALLATION

安裝與啟動方式

  1. 由官方 Releases 取得專用配布 ZIP，解壓至可寫入資料夾；不要以 GitHub 自動產生的 Source code ZIP 代替。
  2. 確認根目錄有 AGENTS.md、package.json、server.mjs、public/、scripts/、skills/。本次也確認同捆素體 assets/donor/weighted-body.blend 存在。
  3. 讓 Agent 讀取這一版的 AGENTS.md，再依製作階段閱讀 Skill。本次以簡體中文與 Agent 溝通；報告沿用網站的繁體中文。
  4. 在套件根目錄啟動。標準配布套件無需先執行 npm install。[1][2]
node --version
# 先切換至含 package.json 的套件根目錄
npm.cmd start

本次 Windows 使用 npm.cmd start，對應官方的 npm start。終端回傳：

AI Character Modeling Kit http://127.0.0.1:8766

再讀取首頁，確認 HTTP 200 且內容是 Charakuru。後續曾發生無法存取首頁，重新啟動後恢復 HTTP 200；當時未查明服務停止原因。使用期間需保持服務運行。若埠被占用，應檢查原服務或依套件規則改用其他埠，不要終止不明程序。

應用語言可在 Settings → Language 設為簡體中文。此設定應在實際使用的瀏覽器內確認。

04 / VRM ADD-ON

本次 VRM 擴展安裝紀錄

最初背景檢查找到 Blender 5.2.2 與已啟用的 MCP 擴展，但未找到 VRM 擴展。依使用者指示，從作者的官方 GitHub Release 下載 VRM_Addon_for_Blender-Extension-4_10_4.zip。[3]

下載包的 manifest 宣告 Blender 兼容範圍為 4.2.0 ≤ 版本 < 5.3.0，涵蓋本次的 5.2.2。下載最初遇到連線拒絕，取得工具所需網路執行權限後成功；這是當次執行環境的限制，不代表官方檔案不存在。

以下是本次採用的安裝方式。請替換安裝包位置；Blender 路徑也需符合實際安裝位置。

& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --command extension install-file --repo user_default --enable 'C:\你的下載位置\VRM_Addon_for_Blender-Extension-4_10_4.zip'

程序回傳 STATUS Installed "vrm"。接著以新的 Blender 背景程序載入偏好設定，驗證結果如下：

module: bl_ext.user_default.vrm
enabled: true
material_extension: true
export_operator: true

這證明擴展能自動載入，且材質擴展和 VRM 匯出 operator 已註冊；不等同於完成角色匯出測試。若 Blender 視窗在安裝前已開啟，需先儲存工作，再重啟以載入擴展。

05 / CONNECTION

瀏覽器與 MCP 排查經驗

Chrome 登入與 Agent 可操作是兩件事

使用者最初在獨立 Chrome 登入 Tripo。Agent 能找到 Tripo 視窗，但電腦控制工具無法可靠辨識目前網址，因此停止操作。這證明控制通道受阻，不代表 Tripo 未登入。

排查中也曾遇到內置瀏覽器技能檔缺失，以及預期檢查 Tripo 卻讀到 Charakuru 的情況。前者是工具可用性問題，後者是分頁選擇問題，都不能據此判定帳戶登入失敗。Chrome 官方擴展設定曾被列為可行路徑，但本次未驗證該路徑成功。

後續由使用者選擇內置瀏覽器並登入 Tripo；工具更新後，Agent 成功綁定既有分頁、讀到帳戶積分與生成介面。此結果確認登入與頁面讀取；實際上傳、生成、匯出下載尚待驗證。Chrome 與內置瀏覽器使用不同的登入狀態，不能互相代替判斷。[4]

修正 MCP 判斷：不能只靠一次埠查詢

最初查詢監聽埠未回傳結果，Agent 因此說 MCP 未開啟，這個判斷不夠充分。使用者表示已開啟後，重新查看 Blender 畫面，確認 Connected on port 9876，再直接測試 TCP 連線成功，將結論修正為「Blender 端已開啟」。

1 · 擴展已啟用

Blender 能載入擴展，操作面板存在。

2 · 服務可連線

本次已通過 127.0.0.1:9876 的 TCP 連線測試。

3 · Agent 可呼叫

仍需 MCP 客戶端提供工具並成功執行查詢；本次尚未完成。

目前不需要重新安裝 Blender MCP。後續應檢查 Agent 客戶端設定與工具清單，再以讀取場景等唯讀操作驗證完整鏈路。TCP 成功只能證明服務可達，不能取代 MCP 協定與工具呼叫測試。

06 / WORKFLOW

從原圖到 VRM 的使用路徑

以下依本機 1.1.1 套件的 AGENTS.md 與中文教程整理，屬於預定操作流程，尚非本次生成成果。完整設定請對照官方教程。[1][2]

  1. 原圖與部位圖

    匯入有權使用的全身圖。製作含髮頭部與 T 姿勢身體，各四方向，另製作全身三視圖供比例參考。

  2. 審查圖片與選擇模型

    確認設計一致後產生頭、身體各四個候選，分別選定。此階段涉及 Tripo 積分；本次沒有量測整個角色的製作成本。

  3. 材質與比例

    Agent 分割、分類、處理 UV 與貼圖後組裝；使用者檢查頭頸銜接及頭身比例。

  4. 綁定與物理

    依流程取得骨骼位置、傳遞權重，設定頭髮與服裝擺動，再執行技術檢查。

  5. 動作確認與保存

    使用者檢查變形與擺動，填寫模型名稱、作者及使用條件後匯出。保留 VRM、Blend 與完整專案資料夾。

現在可以進行的第一步

  1. 在 Charakuru 點擊 Load original illustration／載入原始插畫。
  2. 點擊 Request images／請求製作圖片。
  3. 點擊 Copy prompt／複製提示詞，將完整請求貼到聊天並送出；只複製不會開始製作。
  4. 保持發出請求的應用分頁開啟。Agent 使用請求中的 agent-session.mjs begin 儲存最新狀態，確認 saved: true 才開始。

不要自行拼湊 Request ID，也不要以舊請求代替目前狀態。圖片階段可以先開始；Blender MCP 的完整呼叫鏈應在 Blender 製作階段前完成。

07 / FINDINGS

實測結論與後續驗證

本次確認 Charakuru 能在這台 Windows 電腦啟動，VRM 擴展安裝可透過 Blender 命令行重現。設定上的主要摩擦來自跨工具銜接：瀏覽器登入、分頁選取、控制工具連線，以及 Blender 服務端和 Agent 客戶端之間的區別。

較可靠的檢查方式是逐層驗證：HTTP 200 確認應用回應；頁面內容確認瀏覽器會話；新 Blender 程序確認擴展載入；TCP 確認服務可達；唯讀 MCP 呼叫才確認 Agent 能使用工具。不能把上一層成功當作下一層成功，也不能把一次查詢未回傳直接解讀為未安裝。

下一輪研究應記錄

  • 完整角色從原圖到 VRM 的耗時、人工介入次數與積分變化。
  • 多方向圖片一致性、候選模型背面與接縫品質。
  • 肩肘髖膝變形、髮絲與服裝物理，以及匯出後材質表現。
  • MCP 場景讀取、Tripo 上傳下載、專案重開與成品回讀結果。

目前沒有角色成品或量化品質測試，不對品質、全流程成功率或節省工時評分。本報告的成果是可重現的安裝紀錄與具體排查經驗；成品測試需另補證據。
